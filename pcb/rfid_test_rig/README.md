# RFID 2×2 Test Rig

Generated by `generate_rfid_rig.py` from `RIG_PLAN.md`. 80×92mm, 4-layer
(F.Cu / In1.Cu / In2.Cu / B.Cu). Validates RFID antenna coupling + mux
switching for the 64-square chessboard before that board is designed.

## ✅ Build status: DRC CLEAN

```
0 error-severity violations, 0 unconnected items
(kicad-cli pcb drc --severity-error, KiCad 10)
```

Key structural changes made during the final convergence pass (beyond the
original plan):

- **Coils are never x-mirrored** (S2/S4 keep normal winding geometry; only
  the component/port layout mirrors). This puts every hot via on its
  square's east side and eliminates the S1/S2/S4 hot-via pile-up that
  caused the original 3 stubborn crossings. Cold vias still follow the
  layout mirror so the jumper's hot pad faces its via.
- **In1.Cu / In2.Cu are used as strip routing layers** (they only carry
  coil copper inside the squares): SENS3's full strip crossing, S0/S1's
  J1 legs, the U2-VCC 3V3 link, the DVDD spur and LEDD0's J1 leg all ride
  the inner layers, escaping the saturated F/B strip.
- **DEMOD_OUT and SHD are manually routed** (the corridor router ran out of
  row slots in the 86.1–87.3 window; RDY_CLK keeps the pinned 86.3 row).
- **Test points moved**: TP2 (21.6,84.0), TP3 (38.6,83.6), TP4 (40.6,81.9).
- **Zone pad connection is FULL (solid)** — hand-solder rig, kills all
  starved-thermal risk.
- The J1/J2 GND link is registered **before** the corridor/trunk routers so
  they dodge it (fixups placed after them re-collided on every regen).
- Effective DRC clearance is **0.2mm** (not 0.15) — margins were tuned to
  ≥0.2 with the 0.5mm copper-edge rule respected.

Silk-only warnings remain (cosmetic). Verify component rotations in
JLCPCB's viewer before paying, as with every board in this project.

## Zero-solder ordering (nothing hand-assembled)

1. **EM4095 first**: JLCPCB → Parts Manager → Order Parts → *Global Sourcing
   Parts* → search `EM4095HMSO16B+` (Mouser stock). 9–20 business days to
   arrive in their warehouse; the PCBA order can only start after it shows
   "Complete". Loose-part fee ≤ $0.078/pc.
2. **PCBA order**: Standard assembly, SMT + THT in one order (J1/J2 headers
   are wave/hand-soldered by JLC). All other parts are LCSC-stocked per
   BOM.csv — no DNP rows, no TBDs.
3. **S3/S4 tanks are factory-fitted**: 2× 100nF C0G 1206 (C97946) = 200nF →
   8.3 µH resonates at 123.6 kHz, inside the EM4095's 100–150 kHz capture
   range. No post-measurement cap swapping required for bring-up; if the
   measured L differs enough to matter, a cap swap is an optimization, not
   a blocker.
4. Rig connects to any ESP32 devboard with DuPont jumper wires on J1/J2.

## What's implemented (mechanical transcription of RIG_PLAN.md)

- **4 coils**: S1/S2 are stacked 3-layer spirals (In1 18t + In2 18t(mirrored)
  + B 18t, series chain, HOT→In1→In2→B→cold), predicted L≈83µH. S3/S4 are
  B.Cu-only 16t spirals, predicted L≈8.3µH. Mirroring (S2/S4) negates rel-x
  of every coordinate per the plan.
- **Hall (UHE4913G) + WS2812 LED + 0Ω cold jumper** per square, inner-zone
  wiring and F.Cu port crossings (SENS/3V3/5V west or east, GND, LEDD
  DOUT/DIN) exactly per plan geometry.
- **Strip**: EM4095 (U1), 2× 74HC4851 mux (U2/U3), R1/tank/zener clamp
  clusters per antenna, J1 (1×12) / J2 (1×6) headers, 8 test points,
  per-side decoupling.
- **GND zone** on F.Cu only, with 4 keepout squares (half-side 15.4mm) so
  the pour never touches coil territory.

## PLAN-DEVIATION log (local nudges made to pass DRC / avoid physical conflicts)

The plan explicitly authorizes local coordinate nudges where "DRC decides."
Every deviation is also marked with a `# PLAN-DEVIATION:` comment at its
location in `generate_rfid_rig.py`. Summary:

1. **J1/J2 header rotation**: plan says rot270; that runs pins **west** with
   increasing pin number. Used **rot90** instead so pins run **east**
   matching the plan's own pin-list ordering.
2. **+3V3/+5V/SENS/LEDD margin routing**: the plan's single full-board-width
   spine row collides with per-square port verticals and (once coil vias
   were properly registered in the collision system) with coil copper.
   Replaced with fixed-column "vertical trunks" per margin
   (`WCOL`/`ECOL` dicts: west 1.2/2.4/3.6/4.8/6.0mm, east 75.0/76.2/77.4mm,
   plus dedicated far-east SENS2/SENS4 columns 78.2/79.0mm), bridged
   west↔east via the top routing corridor (y<5.5, explicitly coil-free per
   plan) or the inter-row channel (y≈37, also coil-free).
3. **A1/A3 and A2/A4 antenna-drop lanes widened** from the plan's 40.6/37.2
   and 73.6/68.5 to 41.1/36.7 and 74.1/68.0 — at the plan's spacing the
   tank-cap clusters of adjacent antennas were only 0.8mm apart (footprints
   physically overlapping).
4. **Tank-cap/zener offset from lane center** tightened from the plan's
   1.3mm to 0.8mm for the same reason (adjacent-cluster spacing).
5. **S2's coil hot via / S4's coil hot via** shortened (stub magnitude
   16.1/16.2 → 14.0/14.6mm) — the plan's symmetric stub length put S1's and
   S2's (and S3's and S4's) hot vias only 0.6-0.8mm apart in the shared
   inter-column gap.
6. **A<n> test points** (TP5-TP8) relocated from the plan-implied feed-line
   position onto each antenna's own vertical run, off the AM<n> zener
   midpoint stitch and off J1's pin7 THT column, to avoid clearance
   violations with unrelated nets/pads.
7. **E5VY / channel-crossing rows** for the LEDD2 corridor (S1↔S2, inter-row
   channel) tuned to a ~0.3mm-wide safe window between S1's DIN port via
   (needs 0.9mm clearance) and S3's own outermost coil turn (invisible to
   the generic router since it isn't axis-aligned) — the single tightest
   spot on the board.

## Known generator bugs fixed during bring-up (documented for future reuse)

- `led_dout/gnd/din/vdd` port-crossing coordinates were double-counting the
  LED footprint's own +3.9mm y-offset (the plan's pad offsets are already
  relative to the *square* center, matching the `wantL` pad-matching dict).
  This misaligned every LED port stub by exactly 3.9mm and was the single
  largest cause of "unconnected" DRC items (fixed → unconnected 57→37).
- `vertical_trunk()`'s per-point `hseg()` call discarded the jogged y and
  placed the via at the *original* requested y — if the exact row was
  blocked and `hseg` jogged elsewhere, the via missed the actual track
  entirely. Fixed by capturing and using `hseg`'s return value (unconnected
  37→28, 3 shorting_items→0).
- `coil` hot/cold vias were created with `via_at()` (a separate helper from
  the general router's `rvia()`) and were invisible to the collision
  registry — later routing could (and did) route straight through them.
  Fixed by having `via_at()`/`seg()` register into the same `segs`/`via_pts`
  tables the router already consults.

## Bring-up procedure

1. **Visual inspection** — check silkscreen ref-des against BOM, confirm no
   solder bridges on the tight tank/zener clusters (courtyard warnings above
   mean these pads are closer together than ideal; hand-solder carefully or
   have the assembly house double-check paste stencil apertures there).
2. **Power-up dry test** — before installing U1/U2/U3, apply +5V/+3V3/GND
   only via J1, confirm no shorts (should draw µA, not amps).
3. **Hall + LED test** — populate U_S<n>H (hall) and D_S<n> (LED) only.
   3.3V/5V present, no RFID field: LED should be addressable via LEDD0 chain
   (J1 pin7 → S3 → S1 → S2 → S4). Hall SENS<n> outputs should read a fixed
   logic level (idle) via J2.
4. **Antenna resonance check** — before installing U1 (EM4095), measure each
   coil's inductance directly at its cold-jumper pads (remove jumper,
   measure across A<n>↔GND at the coil side) with an LCR meter. Compare to
   predicted 83µH (S1/S2) / 8.3µH (S3/S4). **Refit tank cap value** to hit
   125kHz resonance: C = 1/((2π·125kHz)² · L_measured).
5. **Full RFID test** — populate U1, U2, U3. Select antenna via
   S0/S1 + EN0/EN1 (J1 pins 8,9,10,11), present a 125kHz tag, scope
   RDY_CLK/DEMOD_OUT (J1 pins 4,6) and the per-antenna A<n> test points
   (TP5-TP8) for carrier amplitude — should read ≈8V pk on the 83µH
   antennas per predicted V_ANT.
6. **Cross-talk check** — with a tag over S1, confirm S2/S3/S4 (unselected)
   don't false-trigger; this is the whole point of the 2×2 rig before
   committing to a 64-square mux tree.
